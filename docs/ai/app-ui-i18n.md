## Fehler im Store, Zurücksetzen, Kontrast & Hilfe

- **Fehler im Store:** Aktion mit eigener Rückmeldung im Aufrufer (Erfolgs-Toast, Formular) → `throw e`; Knopf ohne eigene Rückmeldung → `reportFailure` (`store/reportFailure.ts`, Toast mit Ursache); reine Hintergrundabrufe → nur Log. Ausnahme `saveCurrentSettings`: Fehler einmalig melden, erneut erst nach einem zwischenzeitlich erfolgreichen Speichern.
- **Zurücksetzen & Kontrast:** Standardwerte je Bereich in `utils/settingDefaults.ts` (Sampler wie `SamplingParams::default`, Server-Tuning, Theme; Bonsai eigene), Anzeige/Knopf `settings/ResetSection.tsx`. Theme-Farben müssen WCAG AA halten: `e2e/contrast.mjs` (Teil von `npm run e2e`) misst alle Themes hell/dunkel; neue Farbtöne für weiße Schrift mindestens Stufe 700 (bzw. `accent-600`), Hinweistext `slate-500` ist in `App.css` je Modus angepasst.
  Neue Einstellungen brauchen einen Satz darunter (`OptionHint` + `aria-describedby`); `e2e/settings-hints.mjs` prüft das.
  Auswahlkarten mit `role="radio"` bekommen `radioGroupKeyDown`/`radioTabIndex` (`utils/radioGroup.ts`, Pfeiltasten, ein Tab-Halt); Dialoge immer über `ModalOverlay` (Fokus-Falle, Escape, Fokus-Rückgabe) – `e2e/keyboard.mjs` prüft das.
- **Hilfe:** `components/HelpDialog.tsx` (`GUIDE_STEPS`, `GLOSSARY_TERMS`, Texte `help.*`/`glossary.*`), geöffnet über `appSlice.isHelpOpen` (Kopfzeile, Befehlspalette); Anleitung `docs/guide-getting-started{,.de,.ru}.md` bei neuen Abläufen nachziehen.
- **Lösungsknöpfe:** `utils/errorFixes.ts` `errorFix(error, store)` ordnet häufige Codes einem Schritt zu (Chat-Banner über `generationFailure.cause`, Toasts über `reportFailure`); neue Codes mit klarer Abhilfe dort ergänzen.

## Oberflächensprachen, Fehlercodes & Spieltexte

- **Oberflächensprachen:** je Sprache eine JSON-Datei, damit neue Sprachen ohne neuen Build gehen. Drei Ebenen, spätere gewinnen je Schlüssel:
  1. mitgeliefert `presets/locales/ui/{de,en,ru,ja}.json` (Japanisch seit 21.10.2026, `__meta.fallback: en`)
  2. Daten-Repo (`locales/ui_registry.json` + `locales/ui/<kürzel>.json`, beim Start nach `<Daten>/locales/ui-hub/`, für mitgelieferte Sprachen nur mit höherer `__meta.version`; Event `ui-languages-changed` → `refreshLanguages`)
  3. eigene Dateien in `<Daten>/locales/ui/` (Import über die Einstellungen `import_ui_language`, Entfernen `remove_ui_language` in den Papierkorb; überleben Updates).
  Import-ID: `__meta.id`, sonst Dateiname. Flache `"schlüssel": "text"`-Paare plus `__meta` (`name`, `englishName`, `author`, `version`, `fallback`); Dateiname = Sprachkürzel (`is_language_id`, `_template.json` wird ignoriert).
  Backend `modules/ui_locales.rs` (`list_ui_languages`, `load_ui_language`, `open_ui_locales_folder` legt `_template.json` aus Englisch an; `ui_text` für das Tray-Menü).
  Frontend: Deutsch ist eingebaut und Typquelle (`i18n/types.ts` → `TranslationKey` aus `de.json`), andere Sprachen lädt `loadLocale` über das Backend; `t()` fällt `Sprache → __meta.fallback → Englisch → Deutsch → Schlüssel` zurück (Englisch lädt `loadLocale` mit; Backend `ui_text` gleich). Inhalte mit `otakusoul_i18n` nehmen ohne eigene Übersetzung die englische (`characters::i18n_translation` / `cardI18n.pickTranslation`), außer in der angegebenen `source_language`; Hub-Registry-Texte (Grundtext Deutsch) ebenso (`registryText`), Startvorschläge `choices[lang] → en`. Sprachlisten nie hart verdrahten, sondern `availableLanguages` aus dem Store nutzen; `refreshLanguages` liest Dateien neu (`localeRevision` rendert neu).
  Neue Schlüssel in **allen** mitgelieferten JSON-Dateien ergänzen (`src/test/i18n.test.ts` prüft Vollständigkeit und Platzhalter); `npm run i18n:check [-- datei.json]` prüft fremde Übersetzungen.
- **Fehler:** Backend `crate::err!("backend.x.y", key = wert)` → JSON-Code → Frontend `errorMessage()` übersetzt über i18n; jeder neue Code braucht Einträge in allen Locales.
- **Spieltexte** (was die App selbst in Geschichten schreibt, `ContentLang::t("englischer Text")`, Sprache = Antwortsprache): Übersetzungen in `otakusoul-data/locales/<kürzel>.json`; die App liefert eine Kopie in `presets/locales/` mit und lädt beim Start im Hintergrund die aktuelle Fassung nach (`content_lang::refresh_locales` → `<Daten>/locales/`, überschreibt die Kopie). Jede Datei dort zählt als Spielsprache; nachgeladen werden die bekannten plus alle installierten Oberflächensprachen. `language_code` erkennt auch Namen installierter Oberflächensprachen („Polski“ → `pl`). `load_locales` erst in `setup` nach `set_resource_dir`. Neue `t()`-Texte im Daten-Repo ergänzen und die Kopie hier aktualisieren.

## App-Lifecycle, Fenster, IPC & E2E-Harness

- **Beenden:** Schließen-X richtet sich nach `close_to_tray` (Standard an): beim ersten Mal Hinweis per Event `close-to-tray-hint` (`hooks/useCloseToTray.ts`), danach verstecken; aus → `exit(0)`. E2E schließt über `e2e/tools/wmclose.py` (WM_DELETE_WINDOW, erzwingt X11). „Beenden“ (Tray) bzw. Updater-Neustart lösen `RunEvent::Exit` aus → `stop_model_servers` (llama, sd, TTS, max. 8 s). Linux beendet Kindprozesse zusätzlich per `PR_SET_PDEATHSIG`; neue Kindprozesse brauchen `kill_on_drop(true)` und unter Linux `PR_SET_PDEATHSIG`.
- **`target/e2e`:** `cargo test`/`clippy` überschreiben `target/debug/otakusoul` mit einer Version ohne eingebettetes Frontend → E2E nutzt `target/e2e`.
- **Preset-Bereinigung bei E2E-Build:** Tauri kopiert `presets/` beim Build nach `target/e2e/debug/presets/`, löscht dort aber nie Dateien, die im Repository entfernt wurden. Nach dem Entfernen oder Umbenennen von Presets (Figuren, Geschichten, Pakete) den Ordner vor `npm run e2e:build` löschen, sonst sehen E2E-Tests und README-Screenshots noch die alten Inhalte.
- **Hauptfenster:** steht in `tauri.conf.json` mit `create: false` und wird in `lib.rs` (`create_main_window`) gebaut, damit `OTAKUSOUL_HOME` auch den Webview-Speicher umlenkt (`<home>/webview`); der E2E-Harness prüft das per Marker.
- **Kein Browser-Gefühl:** `services/browserChrome.ts` unterdrückt das Webview-Kontextmenü (außer in Textfeldern; markierter Text bekommt das App-eigene „Kopieren“-Menü `ui/TextContextMenu.tsx`) und im Release-Build Browser-Kürzel (F5, Strg+R/P/F/U, F12 …), nur deren Standardaktion – App-eigene Tastenkürzel laufen weiter. Eigene Kontextmenüs per React-`onContextMenu` mit `preventDefault` bauen. Den Inspektor gibt es nur in Debug-Builds; das Cargo-Feature `devtools` nicht aktivieren.
- **Gesperrte Desktop-Sitzung (Linux):** WebKit-Screenshots und Animationsabfragen können hängen. E2E dann unter einem separaten Xvfb-Display ausführen (`xvfb-run npm run e2e`); die Desktop-Sperre nicht verändern.
- **Befehlsaufrufe & Cache:** `src/test/commandCheck.test.ts` gleicht jedes `invoke('…', {…})` mit den Rust-Signaturen und `generate_handler!` ab (camelCase-Argumente, Pflichtargumente) – neue Befehle immer registrieren. Vitest 5 hält einen Modul-Cache (`node_modules/.vitest-cache`): nach neuen Rust-Dateien meldet `commandCheck` sonst fälschlich fehlende Befehle → `npx vitest --clearCache`.
- **Wire-Typen:** Neue Rust-Felder in Typen, die auch handgeschrieben in `src/types/index.ts` stehen: `src/types/wireCheck.ts` meldet Abweichungen; dort und in `index.ts` nachziehen.
- **Events:** Tauri-Listener mit `isSubscribed`-Guard (StrictMode), sonst doppelte Tokens.
- **Binärdaten über IPC:** Große Dateien (Avatare, Bewegungen) über `read_file_binary` als `tauri::ipc::Response` (Rohbytes → `ArrayBuffer`); ein `Vec<u8>` ginge als JSON-Zahlenliste über die Brücke (17-MB-VRM: 2,9 s statt 45 ms).
- **E2E-Einstellungen & Startzustand:** E2E, die Einstellungen direkt schreiben, nutzen `saveSettingsAndReload` aus `harness.mjs` (wartet auf das Startspeichern der App, das sonst die geschriebenen Werte überschreibt, und lädt danach neu). `settingsLoaded` ist erst nach `initApp` wahr. Davor speichert `saveCurrentSettings` nichts (sonst überschreiben Standardwerte die Einstellungen) und `refreshCharacters` wählt keinen Charakter; `initApp` öffnet den gespeicherten direkt über `refreshCharacters(settings.active_character_id)`. Tests, die Speichern prüfen, setzen `settingsLoaded: true`.
